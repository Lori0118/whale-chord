# 这一版的六条不足

写在这里不是自谦，是为了让下一个接手的人知道**哪些地方别信它**。

## 1. 唱还得人来修

气口、颤音、重音它不会自己补。谱上没有的东西，它一段也不加。
每一首歌也要先修谱才能跑通：长音要标拖腔、相邻同字要标成两个字、该换气的地方要自己切。

**结果**：这一版停在「念对音」的前一步，不是「会唱歌」。

## 2. 换声会掉字

把一段人声换音色之后，咬字会丢。丢得多的到十几个百分点。
不是参数问题：同一个字在换声前后，ASR 有时能听出、有时听不出；调 index-rate 和 protect 只能缓解，压不到零。

**教训**：验收时必须分别量「源」和「换声后」两层，别把两层的损失算在一起。

## 3. 说的音色还不稳

同一句话重跑一次，音色会飘一点。原因是说话母本是从描述词生成的，同描述同 seed 也不保证逐次一致。

**所以**：音色必须存成文件（`shared/voices.json` 里登记的永远是文件），不能靠「用同样的描述再生成一次」。

## 4. 听不认中文歌词

听能给你音高、节奏、和弦、颤音速率、气声比例、动态范围——这些都能逐条回查。
但它**不认识中文歌词**：没有共振峰、没有自动对齐。中文歌词的识别是另一条路（ASR / 歌词库），不在这一版。

## 5. 只在一块 12G 的卡上跑

唱一首三分钟的歌，要等一会儿。训练和推理都在同一张卡上排队，不是「云端随便扩」。

## 6. 模型不进仓库

权重、训练数据、真人的嗓子样本，一律不进仓库。你得自己下。
这是许可决定的，不是没打包好。

## 还有两条量出来的硬限制

- **手机录音的高频死在通道上**：手机自带录音机 >2.5kHz 只剩零点几个百分点，同算法下原唱干声是 7.78%——差 28 到 700 倍。不是某一次录坏，是「手机 → 文件」这条通道的问题。所以有入口体检：>2.5kHz ≥3% 才合格，1–3% 只能验管线，<1% 重录。
- **绝对值不可信**：颤音幅度会系统性低估，频谱质心跨仪器不可比。所有数只用于**同一套方法下的横向比较**。
